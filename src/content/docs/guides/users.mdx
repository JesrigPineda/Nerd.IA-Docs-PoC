---
title: Trabajar con usuarios
description: Identifica usuarios y consulta sus variables.
---

import { Steps, Tabs, TabItem } from '@astrojs/starlight/components';

Usa un identificador de tu sistema para crear o actualizar al usuario final y, cuando sea necesario, recuperar sus variables asociadas. Esta guía asume que ya tienes `YOUR_TOKEN`, `YOUR_USERNAME` y un valor de plataforma confirmado para tu cuenta.

<Steps>

1. **Elige un identificador externo estable**

   `external_id` representa el identificador único del usuario en el sistema que consume la API. La fuente no publica restricciones de formato; evita asumir longitud, caracteres o normalización.

2. **Crea o actualiza al usuario**

   Envía `external_id` y `platform`, los dos campos marcados como requeridos.

   **Request**

   <Tabs syncKey="users-language">
     <TabItem label="cURL">

   ```bash
   curl --request POST \
     --url 'https://api.nerds.ai/v2.0/YOUR_USERNAME/user/createOrUpdate' \
     --header 'Authorization: Bearer YOUR_TOKEN' \
     --data-raw '{
       "external_id": "USER_EXTERNAL_ID",
       "platform": "YOUR_PLATFORM",
       "data": {
         "language": "es-MX"
       }
     }'
   ```

     </TabItem>
     <TabItem label="JavaScript">

   ```js
   const response = await fetch(
     'https://api.nerds.ai/v2.0/YOUR_USERNAME/user/createOrUpdate',
     {
       method: 'POST',
       headers: {
         Authorization: 'Bearer YOUR_TOKEN',
       },
       body: JSON.stringify({
         external_id: 'USER_EXTERNAL_ID',
         platform: 'YOUR_PLATFORM',
         data: {
           language: 'es-MX',
         },
       }),
     },
   );

   console.log(await response.json());
   ```

     </TabItem>
   </Tabs>

   **Response**

   ```json
   {
     "success": true,
     "resource": {
       "user_id": 815,
       "external_id": "USER_EXTERNAL_ID",
       "bot_enabled": true
     }
   }
   ```

   **Qué significa**

   La operación devuelve el usuario en `resource`. La fuente no explica qué regla determina si se crea o se actualiza.

3. **Consulta variables solo cuando las necesites**

   `GET /{username}/user/variables` acepta `external_id` junto con `platform`, o únicamente `user_id`. Este ejemplo conserva la primera estrategia.

   **Request**

   <Tabs syncKey="users-language">
     <TabItem label="cURL">

   ```bash
   curl --get \
     --url 'https://api.nerds.ai/v2.0/YOUR_USERNAME/user/variables' \
     --header 'Authorization: Bearer YOUR_TOKEN' \
     --data-urlencode 'external_id=USER_EXTERNAL_ID' \
     --data-urlencode 'platform=YOUR_PLATFORM'
   ```

     </TabItem>
     <TabItem label="JavaScript">

   ```js
   const url = new URL(
     'https://api.nerds.ai/v2.0/YOUR_USERNAME/user/variables',
   );
   url.searchParams.set('external_id', 'USER_EXTERNAL_ID');
   url.searchParams.set('platform', 'YOUR_PLATFORM');

   const response = await fetch(url, {
     headers: {
       Authorization: 'Bearer YOUR_TOKEN',
     },
   });

   console.log(await response.json());
   ```

     </TabItem>
   </Tabs>

   **Response**

   ```json
   {
     "success": true,
     "resource": [
       {
         "name": "language",
         "type": "text",
         "value": "es-MX"
       }
     ]
   }
   ```

   **Qué significa**

   `resource` es un arreglo de variables. La fuente indica que `value` puede ser texto, objeto o arreglo de objetos, pero no publica un schema cerrado.

</Steps>

:::caution[Nombre de email inconsistente]
El modelo público usa `email`, mientras que el ejemplo exitoso de create/update usa `user_email`. No programes una suposición silenciosa alrededor de uno de los dos nombres.
:::
